# Nors — personal ops notes dashboard

Status: draft design (approach A approved 2026-09-09)
Name: **`nors`** (Norse mythology; never `opsnotes`) · path: `/nors/`
Host: **penolox-server** (Hetzner) — Caddy + PocketBase already running

## Problem

Burak needs a private, card-based place to keep operator notes about *his*
machine and server: CLI map, how the server is wired, how the vault engine
works. The vault stays the context/decision layer; this surface is the live
ops dashboard an agent (or Burak) can open and extend. Notes should be
selectable as cards, and creatable with AI-agent help — first as
"agent drafts → human publishes", later optionally as an in-app generate
button.

## Non-goals (v1)

- Second database, Docker, or a new long-lived process on Hetzner
- Public notes or team sharing
- Replacing `300-Projects/` / `500-Knowledge/` in the vault
- In-app LLM calls (SpaceXAI / chat UI) — deferred to v2
- Full wiki search, tags graph, or version history UI

## Host stack (already on the box)

Nors does **not** add infra. It rides what penolox-server already runs
(see vault `600-Arsenal/hetzner-penolox-server`):

```
bbp.burakboduroglu.com.tr/nors/
  → Cloudflare edge (TLS, WAF, Access PIN)
  → tunnel `penolox`
  → Caddy  127.0.0.1:8080   (reverse proxy, auto_https off)
  → PocketBase 127.0.0.1:8090
       ├── pb_public/nors/     Solid+Vite build (dashboard)
       ├── collection nors_notes
       └── pb_data             (already in restore-kit backups)
```

| Piece | Role for Nors |
|---|---|
| **Caddy** | Public HTTP front on the box; proxies `/nors/` and API to PocketBase. Access + any path guards live at the edge / Caddyfile the same way `/subs/` does. |
| **PocketBase** | Auth surface (superuser token), `nors_notes` collection, static file host for the built UI. |
| **Cloudflare Access** | Gates `/nors` and `/api/collections/nors_notes`. |
| **restore-kit** | New rows are inside existing `pb_data` — no new backup target. |

No new port, no Docker, no second systemd unit.

## Shape (application)

### Collection: `nors_notes`

| Field | Type | Notes |
|---|---|---|
| `title` | text | Card title |
| `slug` | text (unique) | URL fragment `/nors/#/n/<slug>` |
| `summary` | text | One–two lines on the card |
| `body` | editor / text | Markdown; Mermaid fenced blocks allowed |
| `kind` | select | `diagram` \| `runbook` \| `reference` \| `scratch` |
| `tags` | json or select (multi) | e.g. `cli`, `server`, `vault` |
| `pinned` | bool | Pin to top of dashboard |
| `status` | select | `draft` \| `published` \| `archived` |
| `sort` | number | Manual order among peers |

API rules: **superuser only** (Skadi pattern). Dashboard holds a superuser
token in localStorage (known Access-session tradeoff).

### UI (Solid + Vite → `pb_public/nors/`)

**SolidJS + Vite**, built to static files under `pb_public/nors/`. Bun is the
package manager. PocketBase (behind Caddy) serves the build — no separate
frontend server.

**Micro is a hard constraint.** Every dependency must justify shipped bytes on
the Hetzner box. Prefer zero-dep. Do not pull MB-class kits for convenience.

1. **Dashboard** — cards for `status=published` (drafts in editor mode).
   Filter by `kind` / tag. Pinned → `sort` → `updated`.
2. **Reorder** — drag-and-drop on cards updates `sort`. **Native HTML5 DnD
   first (0 KB).** `@thisbeyond/solid-dnd` (~160 KB unpacked) only if native
   fails UX; never `@dnd-kit` (~1 MB unpacked) or similar.
3. **Reader** — markdown + Mermaid (load Mermaid only when a fence is present;
   prefer a small markdown lib, tree-shake hard).
4. **Editor** — title/summary/body/kind/tags; Save draft / Publish.
5. **New** — empty editor, or paste an agent-drafted markdown blob.

v1 AI path: agent drafts → Burak publishes from `/nors`. In-app LLM = v2.

### Caddy / Access / deploy

- Caddy already proxies the site to PocketBase; `/nors/` is PB public files.
- Cloudflare Access destinations for `/nors` and
  `/api/collections/nors_notes` (mirror `/subs`).
- No unauthenticated public hook at the edge without a Caddy `respond … 404`
  guard (Skadi lesson on `/api/subs/summary`).
- Source of truth: `~/projects/nors`. Install copies migrations + built
  `pb_public/nors` onto `/opt/pocketbase` on Hetzner (Skadi-style script).
